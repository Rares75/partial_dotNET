# BUGS

The starter contains behaviors that contradict ASSIGNMENT.md. Below is every real discrepancy found by reading the starter code and comparing it against the business rules R1-R8 and the API contract.

| Which rule from ASSIGNMENT.md is violated (R1-R8) | Where the problem was in the starter (file, approximate line) | How you discovered it (test, reading, AI) | What you changed |
|---|---|---|---|
| R5 (a booking cannot start in the past; "now" must come from TimeProvider) | src/RoomHub.Api/Services/BookingService.cs, Create() method (~line 10-30); TimeProvider is injected nowhere in the project (verified across all .cs files) | Reading the code: BookingService.Create never compares startUtc with the current time, and a search of the whole project found no TimeProvider / DateTime.UtcNow usage at all. | Inject TimeProvider into the booking creation path and reject a booking whose startUtc is before TimeProvider.GetUtcNow(), returning 400. |
| R6 (maximum booking duration is 4 hours; exactly 4 hours allowed) | src/RoomHub.Api/Services/BookingService.cs, Create() method (~line 15-22, after the endUtc <= startUtc check) | Reading the code: there is no check on (endUtc - startUtc); a booking of any length is accepted. | Add a check that (endUtc - startUtc) <= 4 hours, returning 400 when exceeded. |
| R7 (only two ACTIVE bookings conflict) + R8 (a cancelled booking frees its interval) | src/RoomHub.Api/Services/BookingService.cs, the foreach over bookings.ListForRoom(roomId) (~line 24-28) | Reading the code: the overlap loop iterates every booking and never filters by Status == Active, so a Cancelled booking still blocks the interval, contradicting R8. | Filter the overlap check to Active bookings only (skip Cancelled) so a cancelled booking frees its interval. |
| R7 (bookings that only touch do not overlap) | src/RoomHub.Api/Services/BookingService.cs, overlap condition `existing.StartUtc <= endUtc && startUtc <= existing.EndUtc` (~line 26) | Reading the code: the condition uses <= on both bounds, so when one booking ends exactly when another starts (startUtc == existing.EndUtc) it is wrongly reported as a conflict (409). | Use strict inequalities (existing.StartUtc < endUtc && startUtc < existing.EndUtc) so touching intervals are allowed. |
| R8 (cancelling an already-cancelled booking gives 409) | src/RoomHub.Api/Services/BookingService.cs, Cancel() method (~line 60-64) | Reading the code: Cancel() sets Status = Cancelled unconditionally, so cancelling an already-cancelled booking succeeds with 204 instead of returning 409. | Return 409 when the booking is already Cancelled; only transition Active -> Cancelled. |
